# Daily figures and open days Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose sjvair.com #320/#321 in `@sjvair/sdk` 5.0.0-beta.8: scale
`averaging_hours`/`daily_statistic`/`daily_statistic_label`, the daily figures
and `is_final` on summary rows, four open-day fetchers, and two pure merge
functions.

**Architecture:** Schema fields are added to the existing zod schemas (with
their explicit `interface ... extends z.ZodObject<...>` types, which JSR's
no-slow-types rule needs). The fetchers sit next to the daily fetchers they
mirror. The merges are generic over the row type in a new `lib/open_days.ts`;
the bulk open fetchers reuse `mergeBulkOpenDays` to fold their pages.

**Tech Stack:** Deno 2, TypeScript, zod, `@std/assert`.

**Spec:** `docs/superpowers/specs/2026-11-09-open-days-design.md`

## Global Constraints

- Branch `feature/open-days` (from `origin/release/5.0.0`); PR into
  `release/5.0.0`.
- No fallbacks for older server responses: every new field is required (no
  `.optional()`, `.default()`).
- Types come from zod schemas (`zinfer`); never hand-written when a schema
  exists.
- Every new public function has JSDoc; every module file keeps its
  `@example Usage` / `@module` block.
- Timestamps stay ISO strings as the server sends them.
- Never run `lib/account/mod_test.ts`. Full run:
  `deno test --allow-net --allow-env --ignore=lib/account/mod_test.ts`.
- Tests default to the local stack `http://127.0.0.1:8000`. Never touch
  production.
- No Claude or AI attribution in commits, PRs, docs or comments (no
  `Co-Authored-By` trailers).
- Merging, tagging and publishing each need the user's own explicit yes, every
  time.

## Review Focus

1. **DST:** open and stored rows on either side of an offset change (`-07:00` /
   `-08:00`) must sort by instant, not string → test in Task 3.
2. **Empty open response** (before today's first hour is summarized, ~00:45):
   merges return stored unchanged; bulk fetcher returns `[]` for an empty page 1
   → tests in Tasks 3 and 5.
3. **Owner repeated across bulk pages** with differing rows (pages built a
   minute apart): one entry, first copy's fields and rows win, no repeated day →
   test in Task 5.
4. **`processor: ""` on the bulk open fetcher** must be sent (raw), while
   `undefined` sends nothing (published series) → test in Task 5.
5. **Inputs not mutated:** stored entries' `summaries` arrays stay untouched
   after `mergeBulkOpenDays` → test in Task 3.

### Task 3: Merge functions

**Files:**

- Create: `lib/open_days.ts`
- Modify: `deno.json` (`"./open-days": "./lib/open_days.ts"` in `exports`)
- Modify: `lib/monitors/mod.ts`, `lib/regions/mod.ts`
  (`export { mergeBulkOpenDays, mergeOpenDays } from "../open_days.ts";`)
- Test: create `lib/open_days_test.ts`

**Interfaces:**

- Produces:
  ```ts
  export function mergeOpenDays<T extends { timestamp: string }>(
    stored: ReadonlyArray<T>,
    open: ReadonlyArray<T>,
  ): Array<T>;
  export function mergeBulkOpenDays<
    T extends { id: string; summaries: Array<{ timestamp: string }> },
  >(stored: ReadonlyArray<T>, open: ReadonlyArray<T>): Array<T>;
  ```

- [ ] **Step 1: Write the failing tests** in `lib/open_days_test.ts` (rows as
      minimal `{timestamp, v}` objects; owners as `{id, name, summaries}`):
  - `"stored wins on a shared day"`: stored
    `[{ts "2026-11-08T00:00:00-08:00", v: 1}]`, open
    `[{same ts, v: 2}, {ts "2026-11-09…", v: 3}]` → `[v1, v3]`.
  - `"open-only days are added and sorted"`: stored days 7 and 8, open day 9
    given first → ordered 7, 8, 9.
  - `"sorts by instant across an offset change"`: `"2026-11-01T00:00:00-07:00"`
    and `"2026-11-02T00:00:00-08:00"` and `"2026-10-31T00:00:00-07:00"` come
    back in date order.
  - `"a day repeated in open is kept once, first wins"`.
  - `"empty inputs"`: `([], [])` → `[]`; `(stored, [])` → equal to stored;
    `([], open)` → sorted open.
  - `"inputs not mutated"`: deep-copy before, `assertEquals` after.
  - `"bulk: owner in both merges its rows"`, `"bulk: stored-only owner kept"`,
    `"bulk: open-only owner appended after stored owners"`,
    `"bulk: owner with summaries: [] in open keeps stored rows"`,
    `"bulk: stored owner's fields win"` (stored `name: "a"`, open `name: "b"` →
    `"a"`).
  - `"bulk: duplicate ids in open folded, first entry's fields, no repeated day"`.
  - `"bulk: stored summaries arrays not mutated"`.
- [ ] **Step 2: Run** `deno test lib/open_days_test.ts` — expect FAIL (module
      missing).
- [ ] **Step 3: Implement** both functions with a module JSDoc (`@example Usage`
      pairing `getMonitorSummariesDaily` with `getMonitorSummariesDailyOpen` and
      `mergeOpenDays`, `@module`) and the reading rule from the spec.
      `mergeOpenDays`: a `Set` of stored timestamps, add open rows whose
      timestamp is new (adding each to the set, so a repeat in open is dropped),
      sort by `Date.parse(timestamp)` (stable). `mergeBulkOpenDays`: fold each
      input by `id` into a `Map` (first entry's fields, rows via
      `mergeOpenDays(first.summaries, later.summaries)`), then walk stored
      owners in order, merge each with its open entry, and append open-only
      owners in their order. Always return new arrays and new owner objects
      (`{ ...owner, summaries }`).
- [ ] **Step 4: Run** `deno test lib/open_days_test.ts` and `deno check mod.ts`
      — expect PASS.
- [ ] **Step 5: Commit** `open days: mergeOpenDays and mergeBulkOpenDays`.
